# Workflow Notes

## Defaults

- Canonical template asset: `assets/折旧摊销预测输入模板.xlsx`
- Working workbook: `~/Downloads/折旧摊销预测输入模板.xlsx`
- Bundled engine package: `scripts/depreciation_forecast`

## Expected behavior

- `prepare` creates the working workbook if missing by copying the bundled asset.
- `prepare --reset` replaces the working workbook with the bundled asset.
- `run` executes the bundled Python forecast workflow and writes results back into the same working workbook.
- `run --input "/absolute/path/to/已填写工作簿.xlsx"` uses a project workbook directly and, unless `--output` is supplied, writes results back to that same file.
- Default `run` writes only `预测汇总` and `检查结果` so routine runs stay fast.
- Use `run --with-details` when you want validation output with `资产结果明细（年度）` and `资产结果明细（月度）`.
- `资产结果明细（月度）` uses a 200-year horizontal month timeline, leaves the detailed forecast period undiscounted, and discounts months after `结束日期` back to `结束日期`.
- Both `资产结果明细（年度）` and `资产结果明细（月度）` show discounted values only after `结束日期`; the pre-end-date discounted view is zeroed out.
- Use `--detail-asset-id` when you want a single asset's `详细过程` sheet.
- No external project root or environment variable is required.
- The script returns JSON so the agent can summarize the result without reopening many files manually.

## Input compatibility

- The input sheets use row 3 headers as field identifiers. Extra columns such as asset category or equipment number may be inserted without changing the calculation.
- Required headers must be present exactly once. Missing or duplicate headers are reported in `检查结果`.
- Formula cells do not require a cached value from Excel or WPS. The engine evaluates the formulas generated by the template for `预计尚可使用年限` and direct `=J行号` / `=K行号` renewal-life references.
- Other formulas in required numeric cells are rejected with a clear validation error rather than silently treated as zero.
