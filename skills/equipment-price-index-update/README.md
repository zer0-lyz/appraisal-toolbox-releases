# 设备价格指数更新（PPI）— 技能说明

> 第二届科创大赛 · 评估助理的 vibe coding · 评估三部 · 耿界翔

## 一、技能解决什么问题

资产评估底稿中有一张 **「全年(更新此表数据）」** 工作表，存放 10 个分行业的
**设备价格指数**（工业生产者出厂价格指数 PPI，上年同月=100）月度序列，
它是「价格指数1」表换算**年度重置价指数**的数据源。

这些数据需要**每月跟进更新**。传统做法是人工登录国家统计局网站、逐月复制粘贴，
痛点很明显：

| 痛点 | 后果 |
|---|---|
| 10 个指标 × 多个时间分片，逐月手工取数 | 一次更新耗时以小时计 |
| 指标口径容易取错（如「塑料制品」有大类/中类之别） | 整条序列系统性偏移 0.8~1.0 |
| 无校验手段，不知道有没有漏月、错行 | 底稿错误在报告阶段才暴露 |
| 直接写回底稿易破坏公式、格式 | 底稿损坏，返工成本高 |

**本技能把上述流程全自动化**：一条命令抓数、一条命令核实、一条命令写入，
并且写入过程自动备份、格式零损伤。

## 二、核心设计：基线 + 增量

### 为什么不每次全量抓取

全量抓取需要遍历统计局目录树 + 请求 4 个时间分片 × 10 个指标，**上百次请求、
耗时 1~2 分钟**，且极易触发统计局限流。但关键事实是：**历史值几乎不会变**，
没必要每月重抓。

### 两层数据架构

| 层 | 位置 | 内容 | 更新频率 |
|---|---|---|---|
| **基线** | `data/ppi_baseline.json` | NBS 全量序列 + 底稿现有值快照 | 建立一次，之后只增量合并 |
| 增量 | `_out/nbs_ppi.json` | 仅最近几期 | 每月一次（约 21 秒） |

**技能包自带一份初始基线**（`references/ppi_baseline.json`）：
10 个序列 / **1,939 个数据点**，覆盖 2007-01 ~ 2026-08。
这意味着**新环境开箱即用，不必先做全量抓取**。

`--build` 的取数优先级为「**包内基线打底 → 本次抓取结果覆盖 → 写成本地基线**」，
因此即使只抓到最近几期，历史序列依然是完整的。

> 增量抓完记得执行 `--merge` 并入基线，否则基线会逐渐滞后。
> `--merge` 同时会报告"新增 N 期 / 修正历史值 N 期"——
> 后者用于发现**统计局是否修正了历史数据**。

## 四、快速开始

### 前置条件

```bash
# Python 环境（本项目统一使用 Anaconda）
D:\Anaconda3\python.exe

# 依赖
D:\Anaconda3\Scripts\pip.exe install openpyxl requests pywin32
```

> `pywin32` 仅在**写入原底稿**时需要（走 COM 调用 WPS/Excel）；
> 只做抓取与核实的话不必装。

### 首次使用（建立本地基线，只做一次）

```bash
# 用包内自带基线打底 —— 几秒完成，不发任何网络请求
D:\Anaconda3\python.exe scripts\ppi_baseline.py --build
```

### 日常更新（每月一次）

```bash
# 1. 增量抓取最近 6 期（约 21 秒，自动复用 cid 缓存，跳过目录树遍历）
D:\Anaconda3\python.exe scripts\nbs_ppi.py --recent 6

# 2. 合并进基线（同时报告 NBS 是否修正过历史值）
D:\Anaconda3\python.exe scripts\ppi_baseline.py --merge

# 3. 核实（自动读「基线+增量」，与底稿逐列逐月比对）
D:\Anaconda3\python.exe scripts\verify_ppi.py

# 4. 预览补充（openpyxl 输出到 _out/ 副本，先看效果）
D:\Anaconda3\python.exe scripts\fill_ppi.py

# 5. 落到原底稿（COM/WPS 写入，保证格式，自动备份）
D:\Anaconda3\python.exe scripts\apply_ppi_to_draft.py --dry-run   # 先看计划
D:\Anaconda3\python.exe scripts\apply_ppi_to_draft.py             # 备份后写入
```

> **精简路径**：若只想补最新那几期，可跳过步骤 2、4，
> 直接 `nbs_ppi.py --recent 6` → `apply_ppi_to_draft.py`
> （写入器会自动合并「基线 + 增量」，无需先手工 merge）。

## 五、脚本详解

### ① `nbs_ppi.py` — 数据抓取

从国家统计局抓取分行业 PPI（上年同月=100）。

| 参数 | 作用 |
|---|---|
| `--recent N` | 只抓最近 N 期（含当月），自动启用 cid 缓存 |
| `--since YYYYMM` | 从指定月份抓起 |
| `--use-plan` | 强制复用 cid/indicatorId 缓存 |
| `--list` | 只列计划不取数（顺带刷新缓存） |

**关键技术点**：

- `easyquery.htm` 老接口已于 2026-05 废弃（返回 403），
  当前有效端点为 `.../external/stream/esData`
- 同一指标按 5 年切分成多个 cid，需分别请求后**本地拼接**
- 取数时间范围**必须按各分片自身边界传**，统一传全范围会漏数
- `indicatorId` 跨分片不稳定，每个 cid 都要重新调 `queryIndicatorsByCid` 取映射
- 脚本内置 `REQ_GAP = 1.2` 秒节流，**不要调小**

### ② `ppi_baseline.py` — 基线管理

| 参数 | 作用 |
|---|---|
| `--build` | 以「包内基线 + 本次抓取」建立本地基线 |
| `--merge [文件]` | 把新抓数据合并进基线（并报告历史值修正） |
| `--status` | 查看基线状态（有哪些期、最新期） |

### ③ `verify_ppi.py` — 数据核实

把 NBS 数据与底稿「全年(更新此表数据）」**逐列逐月比对**，
输出「一致 / 不一致 / 底稿缺 / NBS缺」四类统计与差异明细，
并生成可直接用于回填的"待补清单"（写入 `_out/ppi_verify.json`）。

**差异判读标准（关键）**：

| 差异幅度 | 判定 | 处理方式 |
|---|---|---|
| 完全一致 | 正常 | 无需处理 |
| **≤ 0.05** | **精度差异** | **不要改**。底稿 D~K 列存 2 位小数（如 `102.57`），NBS 官网发布 1 位小数（`102.6`），底稿更精细 |
| **> 0.1** | **口径错误** | 必须查指标是否取对（典型为 F 列） |

### ④ `fill_ppi.py` — 预览补充

用 openpyxl 输出到 `_out/` 副本，用于**先看效果再落地**。

| 参数 | 作用 |
|---|---|
| `--inplace` | 直接改原底稿（自动带时间戳备份） |
| `--tolerance 0.1` | 把 ±0.1 内的差异也视为一致（默认 0.005） |

> ⚠️ openpyxl 保存会**清空全表公式的缓存值**，
> 所以该脚本**只用于输出副本预览，不可用于写原底稿**。

### ⑤ `apply_ppi_to_draft.py` — 写入原底稿（生产环境必用）

走 **COM（WPS 原生）** 写入，**公式缓存值、名称定义、图片、批注、Table 全部原样保留**。

**五重安全设计**：

1. **默认自动备份**（带时间戳），备份失败立即中止
2. 走 COM（WPS 原生），结构零损伤
3. **只补不覆盖**——底稿已有值一律不动（避免用 1 位小数覆盖 2 位小数，降低精度）
4. 写入后**强制格式**：宋体 10 号、数值型、保留两位小数
5. **自动处理新增未来月份行**：复制上期行格式，补 A/B/C 三列（月末日期/年/月）

| 参数 | 作用 |
|---|---|
| `--dry-run` | 只输出写入计划，不动文件 |
| `--draft <路径>` | 指定底稿路径 |
| `--json <文件>` | 指定数据源，跳过「基线+增量」合并 |

## 七、关键事实与避坑指南

### 坑 1：统计局接口已改版

> `easyquery.htm` 于 **2026-05 废弃**，现返回 **403 + WAF 拦截**（`reason:UrlACL`）。
> 网上多数教程仍在讲老接口，照抄必然失败。

三步走新接口（基础地址 `https://data.stats.gov.cn/dg/website/publicrelease/web/external`）：

| 步 | 接口 | 方法 | 用途 |
|---|---|---|---|
| 1 | `/new/queryIndexTreeAsync?pid=&code=1` | GET | 目录树（`code=1` 月度数据） |
| 2 | `/new/queryIndicatorsByCid?cid=<cid>` | GET | 数据集下的指标列表 |
| 3 | `/stream/esData` | POST | 取数 |

> **端点名会变**。文档常写 `/getEsDataByCidAndDt`，但该路径实测 404；
> 当前有效的是 `/stream/esData`。若将来再 404，改 `nbs_ppi.py` 里的路径常量即可。

### 坑 2：别用 Content-Type 判断成败（本技能最大的坑）

实测 NBS **正常返回也标 `Content-Type: text/html`**，body 却是合法 JSON。
曾据此误判为"被限流"，白等十几分钟。

**唯一可靠判据是 body 能否 `json.loads`**：

| body 内容 | 含义 |
|---|---|
| 合法 JSON（`{"data":…}`） | ✅ 正常调用（即使 Content-Type 是 text/html） |
| `<html>… Please enable JavaScript …` | ❌ 触发 JS 人机验证（真限流） |

**不要只看状态码**——限流时状态码仍是 200。

### 坑 3：cid 缓存失效表现为"全部取数为空"

cid/indicatorId 缓存在 `_out/nbs_ppi_plan.json`（35 条，含各分片 sdate/edate）。
若统计局新增分片导致缓存失效，**症状是所有 10 个序列取数全为空**。
处理：删掉该文件重跑即可（脚本会提示）。

### 坑 4：底稿早期数据无法核实

两边数据起点不同，程序只核实重叠区间：

| 列 | 底稿起点 | NBS 序列起点 |
|---|---|---|
| D/E/F/I/J/K | 1995~1996 | 2007-01（D/F/I）· 2014-01（E/J/K） |
| G/H | 2002-04 | 2007-01 |
| L/M | 2014-01 | 2014-01 |

> **不要用本技能的数据去覆盖底稿 2007 年之前那一段**（口径不同）。

## 八、写入格式要求

补进去的值必须是 **宋体 10 号、数值型、保留两位小数**。
`apply_ppi_to_draft.py` 逐格落实三项：

1. **数值** — 写 `float(val)`，不是字符串（文本型会导致后续计算失效）
2. **字体** — `Font.Name = '宋体'`、`Font.Size = 10`
3. **数字格式** — 沿用该格现有格式；若不含 `0.00` 才补默认
   （L 列 `###,###,###,###,##0.00`、M 列 `#,##0.00_ `）

> 实测本底稿 L/M 列的空白格**本就带好这三项**，所以脚本报告
> "修正字体 0 处、修正数字格式 0 处"是**正常结果**——脚本是兜底，
> 底稿没坏就不动。

**新增未来月份行**：底稿数据区 R4~R372，R373 之后没有预留行（默认 Times New Roman 12）。
下月数据发布后须新增行，脚本已自动处理（复制格式 + 补 A/B/C 三列）。
注意 A 列存的是**月末日期**（如 `2026-08-31`），不是月初。

## 十二、使用边界

- 数据**仅供内部核价参考**，正式报告引用需注明来源与取数日期
- **本地基线 `data/ppi_baseline.json` 是长期资产，勿删**——它同时是"已有数据"的存档
- **包内基线含建立时的底稿快照**（`draft_snapshot`），那是原项目的记录。
  **换项目后请重新 `--build`**，否则 `--status` 显示的底稿期范围是旧项目的、会误导
- 抓取依赖公网可达 `data.stats.gov.cn`；被限流时脚本会重试 4 次并给出明确提示，
  但**不会自动长时间等待**
- 真限流后需等待较长时间（实测等 2 分钟仍被拦）
